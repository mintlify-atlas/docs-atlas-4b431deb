DataService is the single source of truth for all persistent player data in Shattered Reality. It wraps the community `ProfileStore` library to handle session management, reconciliation, and safe shutdown saves. On every player join the profile is loaded, normalized, and applied to the player's attributes so downstream systems can read settings from `player:GetAttribute("Setting_*")` without touching the data store directly.

## Architecture

```
PlayerAdded
  └─ ProfileStore:StartSessionAsync(userId)
       └─ profile:Reconcile()         -- fills missing keys with Template defaults
       └─ normalizeProfileData()      -- inventory cleanup, visibility filter, emote migration
       └─ applySettingsAttributes()   -- writes Setting_* attributes onto the Player instance

PlayerRemoving
  └─ profile:EndSession()            -- triggers auto-save
```

A `Maid` instance cleans up both the `PlayerAdded` and `PlayerRemoving` connections if the service is ever torn down during testing.

<Note>
The Maid pattern collects RBXScriptConnections and threads with `maid:Give(connection)`. When `maid:Destroy()` is called all collected items are disconnected or cancelled in one pass. This prevents memory leaks when hot-reloading services in Studio.
</Note>

## Data Template

Every new player profile starts from this template:

```lua
DataService.Template = {
    Fragments                  = 0,
    Bloodlust                  = 1,
    KillerChance               = 0,
    ConsecutiveKillerRounds    = 0,
    HitIndicator = {
        Scale       = 1,
        Color       = {1, 1, 1},
        StrokeColor = {0.15, 0.15, 0.15},
    },
    DevSettings = {
        DevMode   = false,
        ShowHitbox = false,
    },
    Settings                   = {},
    PurchasedKillers           = {"JohnDoe", "c00lkidd"},
    PurchasedSurvivors         = {"Brickbattler", "Vintage"},
    EquippedEmotes             = { [1] = {"IMissTheQuiet","JevilDance","Static","WithFriends","Aura"}, [2] = {} },
    EquippedKiller             = "JohnDoe",
    EquippedSurvivor           = "Brickbattler",
    SelectedSkins              = { Killers = {}, Survivors = {} },
    CharacterAccessOverrides   = { Killers = {}, Survivors = {} },
    SuppressAutoInventoryGrants = false,
}
```

## Default Actors

```lua
local DEFAULT_ACTORS = {
    Killers   = {"JohnDoe"},
    Survivors = {"Brickbattler", "Vintage"},
}
local DEFAULT_VISIBLE = {
    Killers   = {JohnDoe = true},
    Survivors = {Brickbattler = true, Vintage = true},
}
```

On every profile load `normalizeProfileData` guarantees that `JohnDoe` is in `PurchasedKillers` and both `Brickbattler` and `Vintage` are in `PurchasedSurvivors`. Characters not present in `DEFAULT_VISIBLE` require a `CharacterAccessOverrides` entry to remain in the player's inventory — otherwise they are filtered out to protect unreleased content from slipping through.

## Settings

All settings are validated server-side against three allowlists before being stored. Clients cannot write arbitrary keys or out-of-range numbers.

## Server-Side Validation

`SaveSettings` — the `Delta.Function` handler for client save requests — only writes keys that appear in `BOOLEAN_SETTINGS`, `NUMBER_SETTINGS`, or `STRING_SETTINGS`. Unknown keys in the payload are silently dropped:

```lua
-- Only keys present in BOOLEAN_SETTINGS are written
for key in pairs(BOOLEAN_SETTINGS) do
    if typeof(payload.Settings[key]) == "boolean" then
        data.Settings[key] = payload.Settings[key]
    end
end

-- Number keys are clamped to their registered range
for key, range in pairs(NUMBER_SETTINGS) do
    if typeof(payload.Settings[key]) == "number" then
        data.Settings[key] = math.clamp(payload.Settings[key], range[1], range[2])
    end
end
```

After writing, `applySettingsAttributes` propagates every setting back onto the `Player` instance as `Setting_KEY` attributes so server-side game code never needs to touch the profile store for per-frame reads.

## Public API

<Accordion title="DataService:GetData(player) → Profile?">
Returns the active `ProfileStore` profile for `player`, or `nil` if it has not loaded yet.
</Accordion>

<Accordion title="DataService:WaitForData(player, timeout) → Profile?">
Polls every 50 ms until the profile is available or `timeout` seconds elapse. Defaults to a 5-second timeout.

```lua
local profile = DataService:WaitForData(player, 10)
if profile and profile.Data then
    -- safe to read profile.Data here
end
```
</Accordion>

<Accordion title="DataService:SetCharacterAccessOverride(player, actorType, actorName, enabled)">
Grants or revokes direct access to a character that isn't in `DEFAULT_VISIBLE`. `actorType` is `"Killers"` or `"Survivors"`.

```lua
-- Grant a player access to a limited character
DataService:SetCharacterAccessOverride(player, "Killers", "SpecialKiller", true)
```
</Accordion>

## Network Functions

DataService registers three `DeltaNetwork` functions:

| Function | Direction | Description |
|---|---|---|
| `GetData` | Server → Client | Returns the player's full `{Data = ...}` table after normalization |
| `GetSettings` | Server → Client | Returns `profile.Data` (settings slice) |
| `SaveSettings` | Client → Server | Validates and persists a settings payload; returns `(bool, message)` |

<Tip>
To give a player currency during development without touching ProfileStore directly, use the `GivePlayerMoney` admin command from the mod panel. It writes to `profile.Data.Fragments`, updates the `leaderstats` value live, and calls `profile:Save()` — so the change is durable and doesn't leave the profile in a dirty state.
</Tip>
