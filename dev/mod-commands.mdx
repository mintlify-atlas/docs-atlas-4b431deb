The mod panel is an in-game interface accessible to players whose account rank meets or exceeds `Moderator`, or to anyone in a private server or the place owner's session. Commands are loaded dynamically from the `Commands` folder at runtime — each `ModuleScript` exports a definition table and an `Execute` function. `ModPanelService` validates rank, server context, and payload before dispatching execution and logging the result to `WebhookService`.

## Rank & Server Context

Every command carries two access constraints:

- **`RequiredRank`** — a string key resolved via `RankTranslations` (e.g. `"Moderator"`). In public servers the caller must meet or exceed this rank. In private servers the rank check is relaxed: any player in a private server can execute commands that list `"PrivateServers"` in `AllowedIn`, regardless of rank.
- **`AllowedIn`** — an array of strings: `"PublicServers"`, `"PrivateServers"`, or both. Commands not permitted for the current server type are rejected before `Execute` is called.

All commands in this game set `AllowedIn = {"PrivateServers", "PublicServers"}` and `RequiredRank = "Moderator"`.

## Command Format

Each command module exports a table with this shape:

```lua
{
    Id               = "command_id",        -- unique string identifier
    DisplayName      = "Human Name",        -- shown in the panel UI
    Order            = 1,                   -- sort order (lower = higher)
    Executable       = true,                -- false = display-only toggle
    ResetOnExecution = false,               -- resets input fields after run
    AllowedIn        = {"PrivateServers", "PublicServers"},
    RequiredRank     = "Moderator",
    Inputs           = {                    -- array of input descriptors
        { Id = "field_id", Type = "string", DisplayName = "Label", ... }
    },
}
```

`GetDisplayName()` can be implemented on any module to return a dynamic label (e.g. showing the current toggle state).

|---|---|

</Warning>

## DefaultToggle Pattern

Commands that simply read and write a single workspace attribute follow the `DefaultToggle` pattern. The `Executable` field is set to `false` for the base template (`default_toggle` ID), meaning the button is display-only. Real toggle commands (e.g. `DisableTimer`, `EnableFriendlyFire`) override `Execute` to flip their attribute and update `GetDisplayName` to reflect the live value:

```lua
function module:GetDisplayName()
    return "Disable Timer Currently: "
        .. (workspace:GetAttribute("NoTimer") == true and "True" or "False")
end

function module:Execute()
    local noTimer = not (workspace:GetAttribute("NoTimer") == true)
    workspace:SetAttribute("NoTimer", noTimer)
    return true, noTimer and "Timer disabled." or "Timer enabled.", "success"
end
```

The `DisplayedAttribute` field (used by `DisableTimer` and `MaxKillerCap`) tells the client panel which workspace attribute to watch for live value display without re-fetching the command list.

<Note>
All command executions — successful or failed — are logged to `WebhookService:LogCommand()` with `source = "ModPanel"`, the executor's player object, the command ID, the raw payload, and the result message. Rate limiting on `RunModPanelCommand` allows a maximum of 10 calls per 5-second window per player.
</Note>
