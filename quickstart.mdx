Getting a working local development environment for Shattered Reality takes only a few minutes. The project is structured as a file-based Rojo source tree — there is no monolithic `.rbxl` file checked into the repository. Instead, every script, module, and folder maps to a path on disk, and Rojo syncs them into Studio live. The steps below walk from a clean clone through your first successful two-player playtest.

<Note>
  The `workspace.Testing` attribute controls which assets are loaded into the workspace at server startup. When set to `true`, `Server.server.luau` destroys any existing `TestLobby` and replaces it with `StudioAssets` — a stripped-down environment suitable for local testing. When `false` (production), the full `TestLobby` map is loaded instead. You can toggle this attribute at runtime; the server watches for the `GetAttributeChangedSignal("Testing")` event and refreshes assets automatically.
</Note>

## Prerequisites

Before you begin, make sure you have the following installed and ready:

- **Roblox Studio** — download from [roblox.com/create](https://www.roblox.com/create)
- **Rojo** — the file-sync plugin for Studio ([rojo.space](https://rojo.space)); version 7.x is required
- **Git** — to clone the repository
- Basic familiarity with **Luau** syntax and Roblox Studio's Explorer/Properties panels

## Setup Steps

<Steps>
  <Step title="Clone the repository">
    Clone the Shattered Reality source repository to a local directory:

    ```bash
    git clone https://github.com/cenowillceno/SRCode.git
    cd SRCode
    ```

    The root of the repo maps directly to the Roblox DataModel — you will see top-level folders like `ReplicatedStorage/`, `ServerScriptService/`, `StarterPlayerScripts/`, `StarterCharacterScripts/`, `ReplicatedFirst/`, and `ServerStorage/`.
  </Step>

  <Step title="Start the Rojo server">
    From the repository root, start the Rojo development server:

    ```bash
    rojo serve
    ```

    Rojo will watch the source tree for file changes and expose a local sync endpoint (default `localhost:34872`). Keep this terminal open throughout your session.
  </Step>

  <Step title="Connect Studio to Rojo">
    Open Roblox Studio to a **blank baseplate** project. In Studio, open the Rojo plugin panel and click **Connect**. Rojo will populate the Explorer with all folders and scripts from the repo, mapping each file path to the correct Roblox service:

    | Disk path | Roblox service |
    |---|---|
    | `ReplicatedStorage/` | `game.ReplicatedStorage` |
    | `ServerScriptService/` | `game.ServerScriptService` |
    | `StarterPlayerScripts/` | `game.StarterPlayer.StarterPlayerScripts` |
    | `StarterCharacterScripts/` | `game.StarterPlayer.StarterCharacterScripts` |
    | `ReplicatedFirst/` | `game.ReplicatedFirst` |
    | `ServerStorage/` | `game.ServerStorage` |

    Verify the tree looks correct in the Explorer before proceeding.
  </Step>

  <Step title="Enable Testing mode">
    In the Studio Explorer, select `Workspace`. In the **Properties** panel, find the **Attributes** section and set `Testing` to `true` (boolean).

    This tells `Server.server.luau` to load `StudioAssets` into the workspace instead of the production `TestLobby`, giving you a minimal environment with no extraneous map geometry:

    ```lua
    -- Server.server.luau (excerpt)
    local function loadTestingAssets()
        local testing = workspace:GetAttribute("Testing")
        local assets = ServerStorage:FindFirstChild("Assets")
        local randomAssets = assets and assets:FindFirstChild("Random")

        if testing == true then
            local existingLobby = workspace:FindFirstChild("TestLobby")
            if existingLobby then
                existingLobby:Destroy()
            end
            replaceWorkspaceAsset(
                randomAssets and randomAssets:FindFirstChild("StudioAssets"),
                "StudioAssets"
            )
        else
            -- production path: loads TestLobby
            replaceWorkspaceAsset(testLobby, "TestLobby")
        end
    end

    workspace:GetAttributeChangedSignal("Testing"):Connect(function()
        print("[Testing] Testing changed; refreshing Workspace assets")
        loadTestingAssets()
    end)
    ```
  </Step>

  <Step title="Hit Play — verify the server banner">
    Press **Play** in Studio (solo mode). The server bootstrap runs `Server.server.luau`, which requires every service via `Starter:LoadModules`, calls each module's `Init()`, then prints the startup banner to the **Output** panel via `TestService:Message`.

    Look for output resembling:

    ```
          _____                    _____          
         /\    \                  /\    \         
        /:::\    \                /:::\    \        
    ...

    Successfully compiled the ShatteredCode Server Framework

    Total time to compile: 1.84 seconds
    Total components loaded: 17
    Roblox Version: 0.623.1.6230491
    Branch: STUDIO
    Release: 2025-01-15T10:32:00Z

    There was 0 module(s) that went past the threshold of 1 second(s):
    ```

    If you see loader errors in the Output, they will also be forwarded to any connected clients via the `LoaderErrorNotice` RemoteEvent and displayed as persistent on-screen notifications.
  </Step>

  <Step title="Add a second player to trigger round logic">
    A round will not start with only one player. To test the full round lifecycle:

    1. In Studio, go to the **Test** tab in the ribbon.
    2. Set **Players** to `2` and click **Start** (or use **Local Server** mode).
    3. Studio will open two client windows alongside the server. Once both clients join, `RoundService` detects the player count threshold and advances from `Intermission` → `Preparing` → `LoadingMap` → `ActorsReady` → `ActiveRound`.

    Watch the Output for `RoundService` state transitions and `ActorService` actor-creation logs confirming that character configs were resolved and actors were spawned.
  </Step>
</Steps>

## What Happens at Startup (Summary)

```lua
-- Server.server.luau — abridged bootstrap sequence
ensureDeltaNetworkFolders()                          -- create DeltaNetwork/Events + Functions
Delta.Function("GetMousePosition", ...)             -- register typed remote
loadTestingAssets()                                 -- load StudioAssets or TestLobby

queueDirectModules(services)                        -- RoundService, DataService, ActorService …
queueDirectModules(infrastructure)                  -- Anticheat, Commands, SoftShutdown
queueDirectModules(gameplay)                        -- combat, role selectors

Starter:LoadModules(moduleQueue, "ServerSystems", {
    CallInit = true,
    CallStart = false,
    CompileThreshold = compile_threshold,           -- warn if any module takes > 1 second
    OnError = function(kind, moduleScript, err) … end,
})

report_compile("ShatteredCode Server Framework")    -- print banner + timing stats
workspace:SetAttribute("GameLoaded", true)          -- signal clients that server is ready
```

<Tip>
  The Shattered Reality codebase is substantial. According to VSCodeCounter stats, `ReplicatedStorage` alone contains **174 Lua files** totalling roughly **18,000 lines of code**. If Studio's compile time feels slow on your first run, that is normal — Rojo's file watcher and Roblox's script compilation pipeline both need a moment to process the full tree. Subsequent runs will be faster thanks to Studio's module cache.
</Tip>
