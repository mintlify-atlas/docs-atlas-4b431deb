Shattered Reality is organized as a file-based Rojo project spread across five Roblox services. Understanding which service owns which code — and why — is the fastest way to orient yourself before touching any system. The sections below walk through each top-level container, drill into the sub-folder conventions, and finish with an annotated startup flow that shows how the pieces connect the moment a server boots.

## Top-Level Service Breakdown

<Accordion title="ReplicatedStorage">
  The largest container in the project. Everything inside replicates to every connected client automatically.

  | Sub-folder | Purpose |
  |---|---|
  | `Modules/Shared/` | Modules that run on **both** the server and the client (hitboxes, status effects, DeltaNetwork, character replication, ragdoll, core utilities) |
  | `Modules/Main/` | Modules that are **client-only** — managers, features, helpers, and UI packages loaded exclusively by `Client.local.luau` |
  | `Characters/` | Per-character data: `Config.luau`, `Manager.luau`, and `Abilities/` (split into `Client` and `Server` sub-folders) |
  | `Assets/` | Skin configs (`Skins/`), emote definitions (`Emotes/`), and the top-level `Assets` init module |
  | `Starter.luau` | The shared module loader — used by both `Server.server.luau` and `Client.local.luau` to require, init, and start ordered lists of modules |
</Accordion>

<Accordion title="ServerScriptService">
  Server-only code. Nothing here replicates to clients.

  | Sub-folder | Purpose |
  |---|---|
  | `Modules/Services/` | Game-logic services: `RoundService`, `ActorService`, `DataService`, `PlayerService`, `RewardsService`, `StatusEffectsService`, `ProjectileService`, `EmoteService`, `FootstepsService`, `VoiceEffectService`, `WebhookService`, `ModPanelService`, `DialogueService`, `CharacterReplication` |
  | `Modules/Infrastructure/` | Cross-cutting server concerns: `Anticheat`, `Commands`, `SoftShutdown`, `ClientAssets` |
  | `Modules/Gameplay/` | Server-side gameplay helpers (combat clashing, role selectors) |
  | `Server.server.luau` | The server entry point — initializes DeltaNetwork, loads testing assets, queues and boots all service modules |
</Accordion>

<Accordion title="StarterPlayerScripts">
  Runs once per player on the client. Contains `Client.local.luau` (the client bootstrap), `CustomShiftLock`, `PlayerModule`, and `Animate.local.luau`.
</Accordion>

<Accordion title="StarterCharacterScripts">
  Character-local scripts: `DirectionalMovement.local.luau`, `Health.local.luau`, `RagdollFix.local.luau`.
</Accordion>

<Accordion title="ReplicatedFirst">
  Loads before the game is fully replicated. Holds loading screen bootstraps (`LoadingScreenBootstrap.local.luau`, `LoadingScreenMobileBootstrap.local.luau`), `DisableShiftLock.local.luau`, `UIStrokeScale.local.luau`, and the `SelectableMaps` folder.
</Accordion>

## ReplicatedStorage/Modules Deep-Dive

### Shared/ — Runs on Both Sides

```
Shared/
├── Core/           -- Maid, Util, Assets, Characters catalog, RankUtil, Abilities, Passives
├── Gameplay/       -- Hitboxes, StatusEffects, CharacterReplication, BezierProjectile,
│                      Ragdoll, SurvivorHighlights, Visuals, Hitindicator
├── Network/        -- DeltaNetwork (typed remotes), ActorNetwork, PosSerdes
├── Packages/       -- Third-party packages: Signal, ProfileStore, etc.
├── Player/         -- Animations, ChatTags, ChatDisable, HeadLook, DynamicCamera,
│                      AutoHeadCamSubject, UI menus (Emotes, PlayerList, Spectating,
│                      ModPanel, Settings), UI misc (LowHealthOverlay, SurvivorDisplay, …)
└── ActorAssets/    -- Shared actor asset references
```

### Main/ — Client-Only

```
Main/
├── Managers/       -- AbilityManager, ActorManager, HealthManager, RoundManager,
│                      SprintManager, StatusManager, MusicManager, SoundManager,
│                      FootstepsManager, CutsceneManager, DialogueManager,
│                      TerrorRadiusManager, UiRuntimeManager, VFXManager,
│                      MultiplierManager, LMSManager
├── Features/       -- Loading screen, ExtraUIs, HitboxVisualizer, LockOnHead,
│                      ServerIdentityLabel, SoftShutdown client-side
├── Helper/         -- ForgeVFX, EffectHelpers, Notifications, UIController,
│                      UtilityRemotes, CustomShiftLock
├── Gameplay/       -- Client gameplay helpers
├── Network/        -- Client networking helpers
├── Core/           -- Client-side core utilities
├── Player/         -- Client player utilities
└── Packages/       -- Client-scoped packages
```

## Characters/ Folder Pattern

Every character — whether Killer or Survivor — follows the same internal structure:

```
Characters/
└── Killers/
    └── !Pursuer/
        ├── Config.luau        -- Static definition: stats, ability metadata, passive data
        ├── Manager.luau       -- Server-side character controller
        └── Abilities/
            ├── Client/        -- Client-side ability visuals and input handling
            └── Server/        -- Server-side ability logic and validation
└── Survivors/
    └── Nova/
        ├── Config/            -- May be split into multiple config modules
        └── Manager.luau       -- Server-side survivor controller
```

<Tip>
  The character name is used as the key into `CharacterCatalog` (`Shared/Core/Characters.luau`). `ActorService` reads this catalog at round-start to resolve which `Config` and `Manager` to load for each spawned actor.
</Tip>

## Assets/ Folder Pattern

```
Assets/
├── Skins/
│   └── <CharacterName>/
│       ├── <SkinName>/
│       │   ├── Config.luau     -- Skin metadata, rarity, asset IDs
│       │   └── Behavior.luau   -- (optional) overrides for skin-specific VFX/SFX
└── Emotes/                     -- Emote animation and metadata definitions
```

## ServerScriptService Infrastructure

```
Infrastructure/
├── Anticheat/
│   ├── init.luau               -- Anticheat entry point; exposes validation API to services
│   ├── AbilityRequestValidator.luau
│   ├── PayloadSanitizer.luau
│   ├── Checks/                 -- Individual rule modules
│   ├── Policies.luau           -- Per-character or per-ability policy tables
│   └── Validation.luau         -- Low-level type and bounds checking
├── Commands/                   -- 20+ admin/debug commands (BanPlayer, ForceNextGamemode,
│                                  SpawnCharacter, GiveStatus, SetPlayerRole, …)
└── SoftShutdown.luau           -- Graceful shutdown with player notification
```

## Server Round-Start Flow

The following steps trace the execution path from the moment `Server.server.luau` runs through to clients receiving their role assignment.

<Steps>
  <Step title="Server.server.luau boots">
    The entry point calls `ensureDeltaNetworkFolders()` to create the `ReplicatedStorage/DeltaNetwork/{Events,Functions}` hierarchy, then registers the `GetMousePosition` typed function. It loads testing assets based on the `workspace.Testing` attribute, then queues all modules under `Services/`, `Infrastructure/`, and `Gameplay/`.
  </Step>
  <Step title="Starter:LoadModules runs">
    `Starter:LoadModules(moduleQueue, "ServerSystems", { CallInit = true, CallStart = false })` requires every queued `ModuleScript` in order, calling each module's `Init()` method after all modules have been required. Slow modules (over the 1-second compile threshold) are recorded and printed in the banner.
  </Step>
  <Step title="RoundService:Init() registers state machine">
    `RoundService` initializes its round state machine (`Intermission → Preparing → LoadingMap → ActorsReady → ActiveRound → RoundEnding`), wires player-added/removed listeners, and starts the intermission countdown.
  </Step>
  <Step title="ActorService:Init() prepares the actor layer">
    `ActorService` registers `Delta.Event` listeners for `ActorCreated`, `ActorDestroyed`, `UseActorAbility`, and `CancelAbilities`. It also sets up the `GetActor` typed remote function so clients can query live actor state.
  </Step>
  <Step title="Round starts — character Configs loaded">
    When the player count threshold is met, `RoundService` advances to `LoadingMap`, selects a map and gamemode, then calls into `ActorService` to spawn characters. `ActorService` reads `CharacterCatalog` to resolve the correct `Config.luau` for the assigned killer and each survivor, applying stat baselines and ability metadata.
  </Step>
  <Step title="DeltaNetwork events fire to clients">
    `ActorCreated` events broadcast each spawned actor's identity (`ActorName`, `ActorSkin`, `ActorType` attributes) to all clients. The `ManageVisuals` event triggers role-specific UI and VFX setup client-side.
  </Step>
  <Step title="Client managers react">
    On the client, `RoundManager` receives the round-state change, `ActorManager` resolves the local player's assigned character, `AbilityManager` initializes the hotbar, `TerrorRadiusManager` begins listening for proximity cues, and `HealthManager` activates the health UI — all driven by the same DeltaNetwork events fired in the previous step.
  </Step>
</Steps>
